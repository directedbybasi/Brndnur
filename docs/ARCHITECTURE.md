# BRNDNUR ADVISORY LLP — SYSTEM ARCHITECTURE & RUNBOOK

This document serves as the authoritative technical architecture reference, developer runbook, and content editing guide for the **BRNDNUR Advisory LLP** website.

---

## 1. ARCHITECTURAL OVERVIEW

The website is an ultra-fast, static site generated using **Astro v5 (Static Output SSG)**, **TypeScript**, and **Tailwind CSS** (configured with `preflight: false` to ensure 100% preservation of bespoke typography, styling, and design tokens).

```
                      +-----------------------------+
                      |     AUTHORITATIVE SOURCES    |
                      +-----------------------------+
                       /             |             \
                      /              |              \
     Design Tokens & CSS      Astro Components       Content Records
    (src/styles/tokens.css)  (src/components/*.astro) (content/blog/KL-*.json)
    (src/styles/global.css)  (src/layouts/*.astro)   (src/pages/**/*.astro)
                      \              |              /
                       \             |             /
                      +-----------------------------+
                      |    ASTRO STATIC COMPILER    |
                      |      (npm run build)        |
                      +-----------------------------+
                                     |
                                     v
                      +-----------------------------+
                      |     STATIC OUTPUT (dist/)   |
                      |   - 234 Static HTML Pages   |
                      |   - Assets & Local WebP/JPG |
                      |   - Apache .htaccess Rules  |
                      |   - Robots.txt & Sitemap    |
                      +-----------------------------+
                                     |
                                     v
                      +-----------------------------+
                      |   HOSTINGER STATIC HOSTING  |
                      +-----------------------------+
```

## 4. CONTENT PIPELINE & REGIONAL GUIDE GENERATION

### Content Records (`content/blog/*.json`)
Each of the 200 regional guide records follows a strict schema:
```json
{
  "id": "KL-001",
  "district": "Thiruvananthapuram",
  "title": "Trademark Registration in Thiruvananthapuram: Local Guide",
  "slug": "trademark-registration-thiruvananthapuram-guide",
  "metaTitle": "Trademark Registration in Thiruvananthapuram | BRNDNUR",
  "metaDescription": "Step-by-step trademark registration guide for businesses in Thiruvananthapuram...",
  "primaryKeyword": "trademark registration thiruvananthapuram",
  "quickAnswer": "...",
  "h2Sections": [
    { "heading": "...", "content": "..." }
  ],
  "faqs": [
    { "question": "...", "answer": "..." }
  ],
  "wordCount": 1250,
  "published": false,
  "status": "draft"
}
```

### Route Generation Logic
- **Production Articles (`src/pages/resources/[slug].astro`):**
  Filters records where `article.published === true`.
- **Preview Articles (`src/pages/resources/preview/[slug].astro`):**
  Builds all 200 regional drafts for review with `robots="noindex, nofollow"` to protect SEO.
- **Resource Hub Cards (`src/pages/resources/index.astro`):**
  Imports all articles via `src/utils/blog.ts`, renders the 4-column Featured Guides, and lists all 200 regional guides with dynamic reading time calculation.

## 5. DEVELOPER EDITING WORKFLOWS

### How to Update Global Header or Navigation
1. Edit `src/components/Header.astro`.
2. Run `npm run build`.
3. The changes immediately propagate across all 234 generated HTML pages.

### How to Update Global Footer or Legal Disclaimers
1. Edit `src/components/Footer.astro`.
2. Run `npm run build`.
3. The changes propagate to all pages.

### How to Update Global Design Tokens (Colors, Radii, Shadows)
1. Edit `src/styles/tokens.css` or `src/styles/global.css`.
2. Test responsive behavior across desktop (1280px), tablet (768px), and mobile (375px).

### How to Publish a Regional Guide
1. Open the target JSON file in `content/blog/KL-XXX.json`.
2. Review and finalize content.
3. Change `"published": false` to `"published": true` and `"status": "draft"` to `"status": "published"`.
4. Run `npm run build`. The guide will now be generated at `/resources/[slug]/` and can be submitted to Google Search Console.

## 6. VERIFICATION, AUDITING & REGRESSION TESTING

### Run Local Development Server
```bash
npm run dev
# Or on port 4545:
npx astro dev --port 4545 --host 0.0.0.0
```

### Run Astro Diagnostic Typecheck
```bash
npx astro check
# Must return: 0 errors, 0 warnings, 0 hints
```

### Run Full Static Production Build
```bash
npm run build
# Compiles all 234 pages in ~2.9 seconds into dist/
```

### Run Automated Comprehensive Website Audit
```bash
python tests/comprehensive_site_audit.py
```
This automated test checks all 234 generated files for:
- 0 broken internal links
- 0 broken local image assets
- Correct single `<h1>` tag structure
- Valid `<title>`, meta description, and canonical tag
- 0 suspiciously empty sections or truncated word counts

### Run Automated Change Propagation Test
```bash
python tests/test_change_propagation.py
```
This script modifies a shared component (`Footer.astro`) and a content record (`KL-001.json`), compiles the project, asserts that output changes appear on target consumer pages, and cleanly restores the code to its original state.

## 7. HOSTINGER STATIC DEPLOYMENT RUNBOOK

1. Run a clean production build:
   ```bash
   npm run build
   ```
2. Run the audit script to confirm zero defects:
   ```bash
   python tests/comprehensive_site_audit.py
   ```
3. The entire content of the `dist/` directory is the deployment payload:
   - Upload the contents of `dist/` into Hostinger's `public_html/` directory via FTP, Git deployment, or Hostinger File Manager.
   - Ensure `dist/.htaccess` is uploaded to handle clean URLs, trailing slashes, and 301 redirects.
4. Verify HTTPS and test live routes in browser.
